## 2025-11-01 - Content Security Policy Hardening and Tab-Nabbing Prevention
**Vulnerability:** Static portfolio files containing links with `target="_blank"` without `rel="noopener noreferrer"` (tab-nabbing hazard), loading external stylesheet (Font Awesome) without Subresource Integrity (SRI), and lacking a Content Security Policy (CSP).
**Learning:** In static HTML-only pages, browser-based security headers (like HSTS, X-Frame-Options, CSP) are not served via HTTP headers when hosted on standard static file hosters like GitHub Pages unless configured via meta tags. A meta CSP must be placed in the first 1024 bytes and immediately after charset to prevent preloading bypasses. Inline JSON-LD scripts also necessitate `'unsafe-inline'` inside `script-src` to be parsed without console errors. Global replacements of HTML attributes risk creating redundant/duplicate attributes if not scoped correctly (e.g. `rel="noopener noreferrer" rel="noopener noreferrer"`).
**Prevention:** Always write robust Python parser scripts instead of raw string/sed replacement to cleanly inject attributes, merge existing `rel` values safely, and include proper Subresource Integrity values on all CDN references. Use a Playwright script to verify CSP.
